# Future credential-entry boundary

R.51 does not collect a credential. `future_credential_entry` raises `R51_LIVE_TRANSPORT_DISABLED` and does not prompt.

A later approved program, which this stage does not contain, would need all of the following before one session:

- A Start-menu Windows Terminal, outside Cursor.
- The reviewed file hash checked by the user first.
- Account identifier typed once, not echoed into a file or a command argument.
- Token typed once with hidden input, not read from `.env`, the environment, or a credential store.
- No copy of either value in source, logs, exception text, filenames, evidence, git, or chat.
- A preview of the two GET names before any connection, without a full URL.
- A new connection factory written in that later stage. Passing the standard HTTPS class into this adapter is refused.
- Stop after instruments and pricing, or on any other status, path, or extra instrument.

Hidden input would still leave the values in process memory. It would not defend a compromised terminal, a debugger, or an automated tool driving the keyboard.

No persistent credential store is created here.
