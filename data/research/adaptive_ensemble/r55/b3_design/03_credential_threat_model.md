# Credential and authorisation threat model

A GET-only client would not make the token read-only. Broker token permission stays `UNKNOWN`. The token may still be allowed to trade. No threat below is closed by this design document. Mitigations are proposed for a later implementation.

Severity uses Critical, High, Medium, and Low. "Blocks Gate 3" means an authenticated session must not be approved until the stated condition is met. Residual risk remains even after that.

| Threat | Severity | Proposed mitigation | Verification test | Residual risk | Blocks a future authenticated session |
| --- | --- | --- | --- | --- | --- |
| Token copied into logs, tracebacks, or debug output | High | Fixed exception codes. No token in `str` or `repr`. Logging libraries not attached. Preview omits the token. | Offline test puts the synthetic token in a fake body and in a raised reader error. Output and exception text must not contain it. | A debugger or an external tracer can still observe the process. | Yes, until the redaction test passes in Gate 2. |
| Account identifier written to a file or a full URL | High | Planner output keeps `{accountID}`. Evidence writer rejects the identifier string. Reports show the path pattern only. | Same redaction test for the synthetic identifier. | The identifier still exists in memory during the session. | Yes, until that test passes. |
| Token resident in process memory | High | Memory-only object, dropped in `finally` on success, failure, and cancel. No swap to disk by this program. | Inspection that the object is not written and that its text form is empty. A test cannot prove RAM is clear. | The process, a crash dump, or another local program can still read memory. Hidden input does not stop that. | Does not by itself forbid Gate 3, but Gate 3 must state this residual risk. It blocks any claim that the token is safe from local inspection. |
| Unrelated code reuses the token | High | Do not import `forex_bot.config` or `forex_bot.oanda_client`. Do not set environment variables. Do not pass the token to any module except the one GET sender. | Import scan and a test that credential environment names are not read or written. | A compromised interpreter can still read the object. | Yes, until the import boundary is tested. |
| Belief that the client is read-only so the token is read-only | Critical | Preview states token permission `UNKNOWN` and that the token may be allowed to trade. No order method is implemented. The user must accept that warning at Gate 3. | Preview text test. Source scan for order paths. | The broker can still accept an order from this token if some other program uses it. | Yes. Gate 3 cannot be granted by calling the client read-only. The warning must be in the approval. |
| Order-capable code runs by mistake | Critical | No order, trade, or position function in the future transport. Banned paths rejected before a client exists. No production import. | Offline tests for those paths and methods. | A later edit could add a path. Hash pinning of the approved executable is required at Gate 3. | Yes, until those tests pass and the approved hash is the one that is run. |
| Hostile or unexpected response body | High | Size cap, JSON parse, schema checks, no raw body stored, fixed error codes. | Malformed JSON, oversize, unexpected instrument, bad numbers. | A body can still be hostile in memory for the moment it is parsed. | Yes, until those tests pass. |
| Redirect moves the request to another host | High | Redirect statuses are not followed and their bodies are not read. Host is fixed. | Fake 302 does not construct a second client. | A compromised first response cannot be fully prevented from having been sent to the original host. | Yes, until the redirect test passes. |
| DNS or TLS substitution | High | Fixed host string, `CERT_REQUIRED`, hostname verification, no custom CA, no host override. | Tests that a weaker context and another host never connect. | A trusted-root compromise or a local TLS interceptor remains possible. | The code controls block Gate 3 until tested. The residual CA risk must be accepted in the Gate 3 text. It is not removed by tests. |
| Partial session: first request fails or second fails | Medium | Stop. No second request after a first failure. No success file unless both validate. Delete a prior success file first. | Two offline cases, one for each request. | The first request, if sent, cannot be undone. Its bytes may have reached the broker. | Yes, until the partial-failure tests pass. The "cannot unsend" fact must be in the Gate 3 warning. |
| User cancels before the first request | Medium | Cancel returns before DNS. Credentials discarded. | Callback test: cancel after confirm, client-constructed count stays 0. | None beyond the user continuing by mistake. | Yes, until that test passes. |
| User cancels after the first request | Medium | Close the socket. Skip request 2. No success file. | Fake cancel flag checked between the two calls. | Request 1 already happened. | The procedure must say this. It blocks Gate 3 if the procedure omits it. |
| Sensitive fields left in the output file | High | Allowlist of evidence fields. Ban balance, NAV, positions, orders, raw, URL, token, and account identifier. | Writer rejects a document that contains those keys or the synthetic secrets. | A future field could be added by mistake. | Yes, until the allowlist test passes. |
| Dirty Git tree captures a secret | High | Never write a token or account identifier into the worktree. Do not commit as part of a session. Output directory contains only the sanitised file. | Redaction scan of the written file. This design does not clean the existing dirty tree. | The tree is already dirty from earlier work. A later manual commit could include an unrelated secret if one were placed there. This session must not be the thing that places it. | Blocks Gate 3 if the procedure writes credentials into the repository. It does not require cleaning the old tree before Gate 1. |

No row is closed by the current B2 executable. B2 never reads a real credential, which removes the exposure only by refusing the session.
