# Aggregation and availability

M5=300, M15=900, H1=3600, H4=14400 seconds, aligned to UTC epoch multiples. Each higher bar requires every ordered completed M5 source bar in its half-open window; duplicate/malformed/out-of-order inputs reject. Mid, bid and ask each use first open, maximum high, minimum low, last close. Missing rows and partial edge windows make a bucket unavailable; no synthetic prices. Completion equals start+duration. At 10:35 the 10:00–11:00 H1 final values are inaccessible; at exactly 11:00 the completed bar is usable under the explicitly assumed zero publication delay. Context expires after one full timeframe interval without a newer completed bar.

D1 never defaults to UTC midnight. Its API requires explicit reviewed UTC session windows, convention and evidence, handles 23/24/25-hour windows, and does not independently authenticate a supplied calendar. Synthetic calendar tests prove coverage arithmetic, not New York timezone/DST calendar correctness. No validated calendar is supplied for this study, so D1 performance is disabled. [OANDA candle parameters](https://developer.oanda.com/rest-live-v20/pricing-ep/) specify daily alignment settings and a New York default; [granularity definitions](https://developer.oanda.com/rest-live-v20/instrument-df/) classify H4 as day-aligned. Our UTC H4 is a declared research alignment and is not asserted equivalent to default broker H4. No authenticated broker requests were made.

Higher-timeframe features reuse warmed-up 50/100-bar MA/ATR/Bollinger formulas with the appropriate interval. A documented continuity hypothesis retains indicator history across Friday-evening to Sunday-evening/Monday-early gaps of 24–72 hours; other gaps reset warm-up. This retains observed history only, never fills prices; weekend-containing outages may still affect inference. M5 retains the original reset-on-any-gap rule unchanged.
