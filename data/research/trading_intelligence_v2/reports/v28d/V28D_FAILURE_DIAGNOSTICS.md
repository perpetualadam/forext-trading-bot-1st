# V2.8D failure diagnostics — LOCAL, publication approval required

failure_diagnostics.py adds a small enumerated metadata encoder/classifier and current-stage context to the existing bounded worker/supervisor. No new HTTP client, credential system, archive, journal or downloader is introduced. The existing exchange optionally reports bounded stages; legacy calls retain their previous exception paths. The bounded connection distinguishes observed DNS/connect/TLS errors; exchange stages distinguish headers/body and fixed HTTP rejection/truncation codes. Validation/publication/accounting failures retain their actual stages.

Persisted diagnostic.json contains only version, session UUID, source/catalogue hashes, predefined reason/stage, optional bounded window index, UNKNOWN_NO_RETRY and retry_allowed=false. The existing result.json records its SHA-256 plus matching reason/stage. The reader checks exact shape, enums, bindings, hash and absence of interrupted publication. A separate process can reopen and verify it after the worker exits.

No token, authorization header, IPC payload, account identifier, complete header set, raw body, environment/configuration value or arbitrary exception string enters diagnostic metadata. Exception strings are compared only to exact trusted in-repository codes and are never persisted. Unknown exceptions remain UNKNOWN_FAILURE. Worker startup exceptions use fixed categories rather than arbitrary exception-class names. stderr remains discarded; safe stage/reason packets provide the needed evidence without logging raw tracebacks.

Connect timeouts and TLS failures are reported only from typed/stage-supported errors. A parent watchdog that fences a blocked worker reports WORKER_DEADLINE_EXCEEDED with the last observed stage; this does not claim a specific underlying network cause. Aggregate expiry is SESSION_DEADLINE_EXCEEDED. WORKER_CRASHED means unexpected process exit before a final protocol result, not proof of an OS-native crash. GLOBAL_LOCK_LOST, SOURCE_BINDING_INVALID and ACCOUNTING_INCONSISTENT use exact known conditions. A stage is the last observed phase, not a guarantee of the exact instruction executing at termination.

The existing journal, global lock, durable reservation, per-window spent markers and single-use checks remain. Diagnostic reason codes never authorise retry, skip or resume. Corrupt accounting is not repaired: null counts plus a safe diagnostic can be published while original claimed/pending evidence stays spent. Interrupted diagnostic/result publication remains an ambiguity requiring review; there is no alternate storage fallback or automatic overwrite. A physically unwritable disk cannot guarantee diagnostic persistence; claimed authority and pending records still prevent reuse.

The 15/120/15-second stage limits, 1,800-second aggregate budget, one-second pacing and 256 MiB cap remain unchanged. Diagnostic bytes use existing reserved accounting headroom. Real grants were not created. All runtime fault hooks are OFFLINE_TEST-only; LIVE fault injection remains refused.
